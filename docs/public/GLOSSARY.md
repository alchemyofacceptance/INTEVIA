# INTEVIA — Plain-Language Glossary

This glossary gives first-time readers a concise route into recurring INTEVIA terms. It is a derivative navigation aid only: it does not replace exact constitutional, governance, repository, Datacron, evidence, or Human-issued sources, and it creates no authority or implementation state. Each source link identifies the nearest public explanation used for orientation; always read the linked object's own status and boundary.

## Core operating terms

- **Governed Human–AI work** — AI-mediated work in which authority, boundaries, evidence, changes, review, correction, and Human judgement remain visible and inspectable. [Source](../../README.md#why-intevia-exists)
- **Human–AI Triad (HAT)** — INTEVIA's operating model for keeping Human authority, meaning work, implementation support, and review distinct rather than collapsing them into one uninspected output stream. [Source](../../README.md#humanai-triad-operating-model)
- **Human Governor** — the Human role that holds authority, judgement, execution accountability, and final approval. [Source](../../README.md#humanai-triad-operating-model)
- **Vision Chamber** — the Human-directed HAT role for meaning, synthesis, doctrine, boundary interpretation, and public/private coherence; it holds no decision authority. [Source](../../README.md#humanai-triad-operating-model)
- **Making Engine** — the Human-directed HAT role for authorised implementation and technical verification; it holds no decision authority. [Source](../../README.md#humanai-triad-operating-model)
- **Delegation Governance** — the discipline that keeps authority visible when AI-mediated work continues beyond one prompt and response. [Source](../../README.md#humanai-triad-operating-model)
- **Review valve** — a governed return point where consequential work comes back to Human judgement before a public claim, commit, irreversible change, or final approval. [Source](../../README.md#humanai-triad-operating-model)

## Development and evidence terms

- **Slice** — a named, bounded unit of implementation work; evidence associated with a Slice establishes only what its exact source records. [Source](../../README.md#evidence-boundary)
- **Datacron** — a Slice lineage record that preserves evidence, decisions, findings, and status only within the boundary declared by that record. [Sources](../../GOVERNANCE_INDEX.md#primary-routes) · [evidence boundary](../../README.md#evidence-boundary)
- **Qualified repository ref** — the exact Git reference recorded for examining repository bytes; it establishes only what is present at that qualified ref. [Source](../architecture/CURRENT_IMPLEMENTATION_CROSSWALK.md#source-precedence)
- **Repository presence** — evidence that named bytes or paths exist at an exact qualified repository ref, not evidence of execution, acceptance, release, or operational capability. [Source](../../README.md#evidence-boundary)
- **Test-definition presence** — evidence that test code exists at an exact qualified repository ref, not evidence that the test was collected, executed, or passed. [Source](../../README.md#evidence-boundary)
- **Recorded execution** — evidence only of the run, actor, date, scope, result, and repository state named by its exact source, not a general current-pass claim. [Source](../../README.md#evidence-boundary)
- **Human acceptance** — an exact Human-issued decision within its declared boundary, not a status inferred from code, tests, documentation, or AI review. [Source](../../README.md#evidence-boundary)
- **Non-claim** — an explicit statement of what the available evidence does not establish, used to prevent readers from overestimating maturity or capability. [Source](../architecture/CURRENT_IMPLEMENTATION_CROSSWALK.md#what-this-crosswalk-cannot-establish)

## Formation terms

- **Organism** — in INTEVIA's formation vocabulary, an organisation within which governed work can be arranged. Architecture documents also use lowercase *organism* as a metaphor for the INTEVIA system itself; the two uses are distinct. Repository documentation establishes no Organism as created, populated, or operational. [Source](../../README.md#hpcc-organisms-and-circles)
- **Circle** — a sub-unit, team, or grouping within an Organism. Repository documentation establishes no Circle as launched, populated, or operational. [Source](../../README.md#hpcc-organisms-and-circles)
- **Cohort** — an ordinary group of learners or participants considered together; in INTEVIA documentation this is distinct from the defined formation label `Circle`. Its appearance does not establish an enrolled, launched, or active cohort. [Source](../../README.md#current-non-claims)
- **HPCC** — the name used in INTEVIA's current public documentation for the Human capability pathway being developed around governed Human–AI work; repository materials do not establish an active certification programme, launched cohort, or launched Circle. [Source](../../README.md#hpcc-organisms-and-circles)
